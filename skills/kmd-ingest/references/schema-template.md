# KB Schema

The KB root is wherever this file lives — the directory can be named
anything (`kb/`, `knowledge/`, or the whole vault). To place it somewhere
non-default, declare it in a `.kmd.json` at the workspace root:
`{"root": "knowledge"}`.

## Directory taxonomy (relative to the KB root)

| Directory | Contains | Page `type` |
|---|---|---|
| `sources/` | Immutable raw material: scraped pages, whitepapers, transcripts. Append-only — never edited, never synthesized content. | — (not pages) |
| `entities/` | People, organizations, products, tools — one page per distinct entity. | `entity` |
| `concepts/` | Domain knowledge, topic explainers, how-things-work. Living pages that improve over time. | `concept` |
| `projects/` | One page per project: status, goals, links to work. | `project` |
| `decisions/` | ADR-style records: context, decision, consequences. | `decision` |
| `reports/` | Promoted point-in-time outputs (scans, analyses, filed-back query answers). | `report` |
| `assets/` | Derived artifacts embedded from pages: charts, images, Marp decks. Not pages. | — (not pages) |

System files (lowercase): `index.md` is generated by `recompile_index.py`
(ships with the kmd-ingest skill) — regenerate after every ingest, never
hand-edit. `log.md` is append-only via `kb_log.py` — never hand-edited.
`.lint/` holds lint reports (operational records, not pages).

## Naming

**Filenames are titles** — Obsidian displays the filename everywhere, so
name pages in natural language: `GPU memory math for LLMs.md`, not
`gpu-memory-math-for-llms.md`. Date-prefix decisions and reports:
`2026-07-16 Vendor scan.md`. Avoid the characters Obsidian forbids in
filenames (`/ \ : # ^ [ ] |`). Filenames are link targets — rename only
with a full link sweep. Sources keep the name they arrived with
(append-only).

## Page frontmatter (required on every page)

```yaml
---
type: entity | concept | project | decision | report
created: YYYY-MM-DD
updated: YYYY-MM-DD             # bump on every edit
author: <name-or-agent-id>      # last substantive reviser
confidence: high | medium | low
sources: ["[[sources/...]]"]    # provenance rule below; named `sources`
                                # because Obsidian recognizes it natively
tags: []
---
```

The body starts on the line immediately after the closing `---` — no blank
line (Obsidian renders it as extra space) — beginning with the H1.

**`confidence`** is the page's epistemic marker — how much to trust its
claims at query time: `high` = multiple independent or authoritative
sources, uncontroversial; `medium` = a single or opinionated source;
`low` = thin or contested provenance. Set it at ingest, let lint recalibrate
it, and hedge answers drawn from anything below `high`.

**Provenance rule:** every page declares where its content came from.
External-world claims point into `sources/`; internal artifacts point at
their origin — another page, a dated note, the project or conversation that
produced them. Reverse rule: every file in `sources/` must be referenced by
at least one page — an unreferenced source is un-ingested intake work,
surfaced by lint.

## Writing style

- **Declarative, present tense. Write the knowledge, not the conversation.**
  Not: "The user asked about X and the assistant explained…"
  Yes: "X works by doing Y. The key insight is Z."
- **Context-complete:** a future session must be able to read the page cold —
  include all relevant context on the page itself.
- **Link everything:** every mentioned concept, entity, or page gets a
  `[[wikilink]]`. Backlinks are how topics self-organize — Obsidian's graph
  and backlink pane only work when links are dense.
- **Cite sources** where applicable (the provenance rule above).
- **Compression over expansion** — condense facts scattered across sources;
  never mirror greppable source content into pages.

## Save vs. skip

Save: non-obvious insights or synthesis · decisions with rationale ·
analyses that took significant effort · comparisons likely to be referenced
again · research findings · concept pages.

Skip: mechanical Q&A (lookup questions with obvious answers) · setup steps
already documented elsewhere · temporary debugging sessions with no lasting
insight · anything already in the KB.

If it's already in the KB, **update the existing page** instead of creating
a duplicate — a new page only for a distinct, linkable concept other pages
will reference.

## Derived outputs

Pages are the primary output, but knowledge often deserves more:

- **Diagrams** — when a structure or flow explains better than prose, embed
  a ` ```mermaid ` block directly in the page (Obsidian renders it).
- **Charts** — when data wants plotting, generate the image (e.g. a
  matplotlib script) into `assets/` and embed it: `![[assets/chart.png]]`.
- **Slide decks** — when a topic warrants presentation, a Marp deck goes in
  `assets/decks/`, linked from the page it derives from.
- **Filed-back answers** — when a query produces a durable, reusable answer
  (a comparison, an analysis), file it back as a page. This is the
  compounding loop: every good answer makes the next one cheaper.

Derived artifacts are synthesis, never sources — and a deck or chart is an
*export from* a page, not a replacement for it.

## Contradictions

When new information conflicts with an existing page, do not silently pick
a side. Mark **both** pages with a callout and let resolution happen
deliberately (lint tracks open contradictions):

On the existing page:

```
> [!contradiction] Conflict with [[New Source]]
> [[Existing Page]] claims X. [[New Source]] says Y.
> Needs resolution. Check dates, context, and primary sources.
```

On the new page or source summary:

```
> [!contradiction] Contradicts [[Existing Page]]
> This source says Y, but the existing page says X. See [[Existing Page]].
```

Remove the callouts once resolved (update the page, cite what settled it).

## Operations

All KB writes follow the **kmd-ingest** skill. Health checks follow the
**kmd-lint** skill. Query is a convention: route through `index.md` / search
first, read only selected pages, file durable answers back as pages.
